# Rails, Wheels and Trains (RWAT)

Самостоятельный мод на поезда для **Minecraft 1.21.1 / NeoForge** (не аддон к Create).

- Пути строятся сплайнами Эрмита, а не из блоков.
- Сервер ведёт состав целиком, а по сети передаются только позиция головы вдоль пути и скорость. Позиции вагонов и тележек каждый клиент вычисляет сам.
- Вагон — это кузов на двух тележках, поэтому в кривых и на уклонах он вписывается естественно.
- Подвижного состава в самом моде нет. Он подключается **паками контента** — обычными паками Minecraft, которые одновременно служат ресурс-паком и дата-паком.

> Проект в разработке, сейчас это прототип.

План работ — [docs/roadmap.md](docs/roadmap.md). [SPEC.md](SPEC.md) — журнал архитектурных решений: он объясняет, почему всё устроено так, но местами устарел; источник правды — код и тесты. Формат паков — [docs/proposals/pack-capabilities.md](docs/proposals/pack-capabilities.md) (что пак может задать сейчас) и будущий справочник автора `docs/pack-format.md`, который будет генерироваться из JSON Schema в `schema/` (фаза 1 карты). Правила для агентов — [CLAUDE.md](CLAUDE.md).

## Требования

- **JDK 21**. Gradle должен запускаться именно на нём: если `JAVA_HOME` указывает на другую Java, сборка упадёт.
- Python 3.9+ (только стандартная библиотека) — для конвертера паков и остальных инструментов из `tools/`.

## Сборка и запуск

```sh
./gradlew build          # jar будет в build/libs/
./gradlew test           # юнит-тесты чистого ядра (путь, кинематика, сцепка)
./gradlew runClient      # клиент для разработки
```

Полезные параметры:

- `./gradlew runClient -PquickPlay="<папка мира>"` — сразу зайти в одиночный мир.
- `./gradlew runClient2` во втором терминале — второй клиент (ник `Dev2`) для проверки мультиплеера.
- `./gradlew runServer` — выделенный сервер в `run/server`.

## Настройки физики

Как играется физика, решает сервер: `config/railswheelsandtrains-server.toml` (копия в `<мир>/serverconfig/` переопределяет его для отдельного мира). Профиль `profile` — `REALISTIC`, `STANDARD` (по умолчанию) или `ARCADE`; при `CUSTOM` действуют отдельные значения из раздела `[physics.custom]`, остальные профили этот раздел не читают. Подробности — в [SPEC.md](SPEC.md), §5.6.

Паки всегда описывают настоящую машину: физика, которую пак не указал, берётся из значений движка (SPEC §6.4).

В том же файле, в разделе `[rails]`, — `max_marker_distance`: как далеко маркер ищет парный маркер, то есть самый длинный сегмент, который строится одним кликом (512 блоков по умолчанию, от 16 до 2048). Чем длиннее сегмент, тем дороже постройка: полотно растеризуется по всей длине, и загружаются все чанки, через которые проходит путь (SPEC §2.2). `clear_gauge` (по умолчанию `false`): постройка рельсами расчищает над новым путём габарит — туннель или выемку под поезд, а не щель высотой в полотно; всё в нём ломается без дропа, жидкости остаются, неломаемое, блоки с содержимым и чужой регион отменяют постройку. Размер габарита — `gauge_half_width` (полуширина от оси пути, 1.9) и `gauge_height` (высота над головкой рельса, 5.5).

Там же раздел `[access]`: `cab_access` — кто попадает в кабины. `OPEN` (по умолчанию) — кто угодно. `KEY` — только игрок с **ключом машиниста** (`driver_key`, где угодно в инвентаре; рецепт — железный слиток над двумя железными самородками): без него не открыть двери в кабину, не сесть в кресло машиниста, не тронуть органы кабины и не сесть на место в неходимой кабине. Операторам (уровень прав 2+) и в творческом режиме ключ не нужен. Подробности — SPEC §9.2.

В том же файле, в разделе `[chunk_loading]`, — прогрузка мира вокруг поездов. `mode`: `MOVING` (по умолчанию) — поезд с машинистом и любой едущий поезд держат загруженными чанки под собой и впереди по ходу; `DRIVEN` — только поезд с машинистом; `OFF` — никакой, поезд едет только там, где мир и так тикает (рядом с игроками). `linger_seconds` (20) — через сколько секунд поезд, оставленный стоять без машиниста, отпускает чанки; `unmanned_seconds` (300) — сколько секунд пробега без машиниста он их держит (0 — пока едет); `max_chunks` (256) — предел чанков на один поезд. Сцепка от этих настроек не зависит: стоящие вагоны цепляются, даже если их чанки не загружены. Подробности — SPEC §2.1.

## Настройки клиента

Настройки меняются прямо в игре: «Моды» → Rails, Wheels And Trains → «Настройки» (Mods → Config). Там же — настройки мира (физика, см. выше); их можно менять только в одиночной игре, не открытой для сети, а на выделенном сервере — правкой файла.

Файл — `config/railswheelsandtrains-client.toml`: `swayStrength` — сила тряски вагонов (0 — без тряски, 1 — по умолчанию, до 3), `cameraSway` — насколько качается взгляд едущего (0 — горизонт не качается), `trainVolume` — громкость поездов поверх ползунка «Дружелюбные существа», `driverHud` — приборы машиниста на экране, `interiorDrawDistance` — с какого расстояния до вагона виден его салон, в блоках (по умолчанию 32; 0 — рисовать всегда). Пак может сделать отдельный тип вагона тряским или плавным: поле `"sway"` в декларации модели, итоговая тряска — `swayStrength` × `"sway"`. Звуки и тряска — SPEC §10.

Клавиши за пультом (настраиваются в «Управлении», категория Rails, Wheels & Trains; действуют только за пультом и с ходьбой не конфликтуют): `W` / `S` — тяга, `D` / `A` — тормоз состава затянуть / отпустить, пробел — реверсор (на стоянке), `H` — тифон, `J` — свисток (пока держишь), `L` — пульт: приборы, свет и страница «Состав» (двери и свет по вагонам). Без назначения по умолчанию: вспомогательный тормоз затянуть / отпустить, ручник своего вагона. Рычаги в кабине — мышью, из кресла или стоя (SPEC §9.2, §9.7).

## Паки контента

Паки лежат в `<папка игры>/rwat_packs/`. В разработке клиент читает `run/rwat_packs/`, а `runClient2` и `runServer` подключают туда же через `-Drwat.packDirs`.

Пак **Matoi Vanilla Pack** (MVP) генерируется из паков Immersive Railroading конвертером [tools/ir2rwat.py](tools/ir2rwat.py):

1. Исходные zip — `MVP-IR-1.8-mc1.12.2-by-FrozeRain.zip` и `MVP-IR-1.7-bugfix-mc1.12.2-by-FrozeRain.zip` (78 и 66 МБ) — лежат в корне репозитория, а готовый пак — в `run/rwat_packs/MatoiVanillaPack/` (734 файла). Это **временно** (решение D3, SPEC §9.6): контент лицензирован как CC BY-NC-ND 4.0, а в репозитории он нужен облачным агентам, чтобы мерить состав и перегенерировать пак. Zip и пак уберут из репозитория (и из истории) после фазы 2 [карты работ](docs/roadmap.md), решение R12; тогда zip придётся класть в корень самому.
2. Чтобы перегенерировать пак: `python -I tools/ir2rwat.py packs/mvp.json`. Он появится в `run/rwat_packs/MatoiVanillaPack/`.

Ручные настройки (физика, двери, интерьер, алиасы, имена, свет) хранятся по файлу на тип в `packs/mvp/<id>.json`: рецепт [packs/mvp.json](packs/mvp.json) подключает папку ключом `"overrides_dir": "mvp"`. Раздел `overrides` самого рецепта тоже читается, но MVP его не использует. Настройки стилей рельсов (`rail_overrides`) и звуков по умолчанию (`sound_defaults`) остаются в рецепте. В `packs/mvp/geometry/` лежат сводки геометрии моделей (`--geometry`): по ним работают тесты пола, дверей и света, когда IR-паков под рукой нет. Сгенерированный пак не правят: меняют оверрайды и запускают конвертер заново.

## Структура

| Путь | Что там |
|---|---|
| `src/main/java/com/muzhik17/trainsmod/` | код мода (пакеты — ниже) |
| `src/main/resources/` | ресурсы мода: языки (en_us, ru_ru), блоки и предметы, миксины, стандартный рельс; подвижного состава в моде нет — он приходит из паков |

| `tools/` | Python-инструменты (ниже) |
| `packs/` | рецепт конвертации MVP `mvp.json`, оверрайды по файлу на тип `mvp/<id>.json`, сводки геометрии `mvp/geometry/` |
| `run/rwat_packs/MatoiVanillaPack/`, `MVP-IR-*.zip` | сгенерированный пак MVP и исходные IR-паки; **временно в репозитории** (см. «Паки контента» и «Лицензия») |
| `docs/` | карта работ `roadmap.md`, аудиты и ревью (`reviews/`), предложения (`proposals/`), инструкции агентам (`agents/`) |

| `CLAUDE.md` | правила для агентов |

### Пакеты кода

**Чистое ядро** — без импортов Minecraft и NeoForge, покрыто юнит-тестами:

| Пакет | Что там |
|---|---|
| `path` | сплайны Эрмита и таблицы длин дуг, граф рельсов, маршруты через стрелки, горловины и крестовины стрелок, растеризация полотна и расчистка габарита, участок пути, оставшийся без графа |
| `kinematics` | тележки и поза кузова на пути, тряска, ходьба пассажира по полу (`RiderWalk`, `FloorCheck`), коллизия корпуса, досягаемость кликов |
| `physics` | продольная физика состава, инерция тяги и тормозов, авто-ручник, профили физики (`PhysicsTuning`) |
| `stock` | тип вагона `WagonType`, разбор его JSON, значения движка по умолчанию, реестр типов, раскладка вагонов в составе (`ConsistComposition`), зоны пола `FloorRegion` |
| `convention` | конвенция IR: роли объектов модели по имени (`ObjectRole`), ось шарнира, значения органов, показания пульта; пока ссылается на `consist.Consist` |

**Адаптеры к игре:**

| Пакет | Что там |
|---|---|
| `consist` | состав (серверное состояние в `SavedData`), сущность вагона, менеджер составов, сцепка, прогрузка чанков, доступ в кабины; предметы: подвижной состав, монтировка, ключ машиниста. Чистые внутри: `Coupling`, `ChunkCover`, `ChunkLease`, `Handles` |
| `rail` | рельсы в мире: маркеры и стрелки, блоки полотна, сеть рельсов (`RailNetwork`), предмет рельсов |
| `network` | пакеты клиент—сервер и серверные проверки в `RwatNetwork` |
| `data` | загрузчики датапаков: типы вагонов и раскладка тайлов рельсов |
| `pack` | поиск папки `rwat_packs/` и подключение каждого пака как ресурс-пака и датапака |
| `client` | клиентская логика: ввод, ходьба, камера, снимки составов, выбор под прицелом; подпакеты `client.render` (вагоны, рельсы, свет), `client.render.model` (OBJ, MTL, `.anim`, декларации моделей и стилей рельсов), `client.gui` (пульт, экраны выбора), `client.sound` (звуки из паков) |
| `mixin` | миксины в Minecraft (коллизия корпуса, посадка и спешивание, камера, клавиши, свет, звук) |
| `compat` | Iris и LambDynLights — по рефлексии, без зависимости на этапе сборки |
| `debug` | команды `/rwat` и `/rwatc`, автосцены и снимки для проверки в игре |
| `platform` | пока пуст (задел под порт на другие версии) |

### Инструменты `tools/`

Python 3.9+, только стандартная библиотека; запуск — `python -I tools/<имя>.py`.

| Файл | Назначение |
|---|---|
| `ir2rwat.py` | конвертер: IR-паки (zip) по рецепту `packs/*.json` → пак RWAT; `--geometry` пишет сводки геометрии моделей |
| `floorgen.py` | ходимый пол вагона по треугольникам модели; вызывается конвертером, отдельно рисует карту пола (`--ascii`, `--png`) |
| `objinfo.py` | замеры модели для разметки: объекты и габариты, органы по группам, высоты пола, двери и свет, которые выводит конвертер |
| `gen_track_bed.py` | blockstates и модели блоков полотна по списку материалов в `rail/BedMaterial.java` |
| `gen_driver_key.py` | текстура предмета «ключ машиниста» (пиксель-арт 16×16) |
