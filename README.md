# Rails, Wheels and Trains (RWAT)

Самостоятельный мод на поезда для **Minecraft 1.21.1 / NeoForge** (не аддон к Create).

- Пути строятся сплайнами Эрмита, а не из блоков.
- Сервер ведёт состав целиком, а по сети передаются только позиция головы вдоль пути и скорость. Позиции вагонов и тележек каждый клиент вычисляет сам.
- Вагон — это кузов на двух тележках, поэтому в кривых и на уклонах он вписывается естественно.
- Подвижного состава в самом моде нет. Он подключается **паками контента** — обычными паками Minecraft, которые одновременно служат ресурс-паком и дата-паком.

> Проект в разработке, сейчас это прототип.

Все архитектурные решения описаны в [SPEC.md](SPEC.md), и это главный документ проекта: решения меняются через правку SPEC.

## Требования

- **JDK 21**. Gradle должен запускаться именно на нём: если `JAVA_HOME` указывает на другую Java, сборка упадёт.
- Python 3.9+ (только стандартная библиотека) — для конвертера паков.

## Сборка и запуск

```sh
./gradlew build          # jar будет в build/libs/
./gradlew test           # юнит-тесты чистого ядра (путь, кинематика, сцепка)
./gradlew runClient      # клиент для разработки
```

Полезные параметры:

- `./gradlew runClient -PquickPlay="<папка мира>"` — сразу зайти в одиночный мир.
- `./gradlew runClient2` во втором терминале — второй клиент (ник `Dev2`) для проверки мультиплеера.
- `./gradlew runServer` — выделенный сервер в `run/server`.

## Настройки физики

Как играется физика, решает сервер: `config/railswheelsandtrains-server.toml` (копия в `<мир>/serverconfig/` переопределяет его для отдельного мира). Профиль `profile` — `REALISTIC`, `STANDARD` (по умолчанию) или `ARCADE`; при `CUSTOM` действуют отдельные значения из раздела `[physics.custom]`, остальные профили этот раздел не читают. Подробности — в [SPEC.md](SPEC.md), §5.6.

Паки всегда описывают настоящую машину: физика, которую пак не указал, берётся из значений движка (SPEC §6.4).

В том же файле, в разделе `[rails]`, — `max_marker_distance`: как далеко маркер ищет парный маркер, то есть самый длинный сегмент, который строится одним кликом (512 блоков по умолчанию, от 16 до 2048). Чем длиннее сегмент, тем дороже постройка: полотно растеризуется по всей длине, и загружаются все чанки, через которые проходит путь (SPEC §2.2).

## Настройки клиента

`config/railswheelsandtrains-client.toml`: `swayStrength` — сила тряски вагонов (0 — без тряски, 1 — по умолчанию, до 3), `cameraSway` — насколько качается взгляд едущего (0 — горизонт не качается), `trainVolume` — громкость поездов поверх ползунка «Дружелюбные существа», `driverHud` — приборы машиниста на экране. За пультом: `H` — тифон, `J` — свисток (пока держишь), `L` — пульт и свет. Звуки и тряска — SPEC §10.

## Паки контента

Паки лежат в `<папка игры>/rwat_packs/`. В разработке клиент читает `run/rwat_packs/`, а `runClient2` и `runServer` подключают туда же через `-Drwat.packDirs`.

Пак **Matoi Vanilla Pack** (MVP) генерируется из паков Immersive Railroading конвертером [tools/ir2rwat.py](tools/ir2rwat.py):

1. Положите в корень проекта `MVP-IR-1.8-mc1.12.2-by-FrozeRain.zip` и `MVP-IR-1.7-bugfix-mc1.12.2-by-FrozeRain.zip`. В репозитории их нет: они лицензированы как CC BY-NC-ND 4.0 и весят по 70+ МБ.
2. Запустите `python -I tools/ir2rwat.py packs/mvp.json`.
3. Пак появится в `run/rwat_packs/MatoiVanillaPack/`.

Ручные настройки (физика, двери, интерьер, алиасы) хранятся в рецепте [packs/mvp.json](packs/mvp.json), в разделе `overrides`. Сгенерированный пак не правят: меняют рецепт и запускают конвертер заново.

## Структура

| Путь | Что там |
|---|---|
| `src/main/java/com/muzhik17/trainsmod/` | код мода: `path`, `kinematics`, `physics` — чистое ядро без импортов Minecraft; `consist`, `rail`, `network`, `client`, `pack`, `stock` — адаптеры к игре |
| `src/test/` | юнит-тесты (JUnit 5) |
| `tools/` | конвертер IR → RWAT |
| `packs/` | рецепты конвертации паков |
| `SPEC.md` | спецификация и журнал решений |
