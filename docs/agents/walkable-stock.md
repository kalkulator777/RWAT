# Разметка состава MVP — инструкция для агента

Ты размечаешь подвижной состав пака MVP (Matoi Vanilla Pack) для мода RWAT (Minecraft 1.21.1, NeoForge). Что нужно сделать:
- **пол** — по чему ходит игрок. Его строит генератор по треугольникам модели, ты проверяешь карту и правишь исключения;
- **двери** — вход и выход, переходы между вагонами, двери между частями вагона. Большинство выводится само;
- **кресло машиниста** у локомотивов и головных вагонов;
- **имена** — русское имя состава и имена групп света для пульта машиниста (клавиша `L`).

Ты смотришь карты генератора и сводки геометрии и проверяешь тестами — это основная работа. Игру можно запустить и в облаке, чтобы посмотреть результат на снимках (раздел 7), но окончательно в игре его смотрит человек.

Ответы и отчёт — на русском (проект ведётся на русском).

## 2. Как это устроено

**Что лежит в репозитории.** Всё, что нужно для работы, — временно, это сторонний контент под CC BY-NC-ND 4.0:
- `MVP-IR-*.zip` в корне — исходные паки IR (из них генератор читает модели);
- `run/rwat_packs/MatoiVanillaPack/` — сгенерированный пак: модели OBJ, текстуры, декларации;
- `packs/mvp/geometry/<id>.json` — сводки геометрии (только числа).

**Где ты работаешь.**
- Пак **генерируется** конвертером `tools/ir2rwat.py` из zip.
- Ручные данные лежат в `packs/mvp/<id>.json`, по файлу на тип. Конвертер накладывает их поверх выведенного: deep merge, `null` удаляет поле.
- **Ты правишь только эти файлы.**

**Что конвертер выводит сам:**
- **Пол** — генератор `tools/floorgen.py`: уровень пола, препятствия в слое тела игрока (полки, сиденья, стенки, закрытые створки), зазор 0.1 у стен, только достижимое от дверей, результат — список коробок. Пассажирским вагонам — всегда; локомотивам и головным вагонам — если в файле типа есть ключ `"floor"` (раздел 3).
- **Двери** типам с полом:
  - из объектов `DOOR_<n>`: `EXTERNAL` — наружные, `CONNECTING` — переход в соседний вагон, остальные — внутренние;
  - из `WIDGET_<n>` дверного размера с `TOGGLE` и анимацией своей группы — внутренние (у плацкарта `DoorTambur`, `DoorToilet`, `DoorKupe`).

  Две створки одного проёма становятся одной дверью. Проёмы на одной группе `CG_` получают общий `"group"` и открываются вместе.

**Чего выведенному обычно не хватает:**
- У локомотивов и кабин — кресла, подножек-проёмов, иногда пола кабины: генератор видит модель, а не смысл (раздел 5).
- Генератор ошибается в косых проходах (диагональная стенка превращается в лесенку, тело 0.6 не пролезает) и там, где пустое место внутри корпуса похоже на пол (капот тепловоза).
- Нет имён групп света. У ДР1 и ВЛ80 в меню видны коды «CCL», «HBL».
- Нет русских имён состава.

**Сводки геометрии `packs/mvp/geometry/<id>.json`:**
- `objects` — bbox каждого объекта модели;
- `floor_levels` — горизонтальные поверхности по высоте, с площадью и габаритом в плане;
- `ir_passenger` — IR-зона пассажиров;
- `derived` — что выведет конвертер (`interior` — сгенерированный пол, `floor` — уровни, число коробок, площадь, где помещается игрок);
- `doors_in_model` — все двери модели, как их выведет конвертер;
- `door_motion` — как движется створка каждой `DOOR_<n>` (раздел 3);
- `animations` — группы IR-анимаций и объекты, которые они двигают;
- `lights` — группы света: светящиеся объекты (`glowing`), фары (`headlights`), сколько деталей салона светит (`inside_parts`), тумблеры с подписями (`switches`).

**Если чего-то из этого нет — остановись и напиши об этом в отчёте.**

### Система координат (модель RWAT = файл типа)

- +Z — вперёд по ходу (у IR перёд −X, сводки уже переведены);
- X — поперёк, Y — вверх;
- головка рельса — y 0.406, пол пассажирских вагонов MVP — около 1.8–1.9, настил ЧМЭ3 — 2.311;
- середина вагона — z = 0, концы — ±длина/2.

## 3. Формат файла `packs/mvp/<id>.json`

```json
{
  "name": {"ru_ru": "ЭР2, головной вагон"},
  "lights": {
    "ER2L": {"en_us": "Saloon light", "ru_ru": "Свет в салоне"}
  },
  "floor": {
    "level": [1.909, 2.2],
    "add": [{ "min": [-0.3, 1.909, 9.0], "max": [0.3, 1.909, 9.8] }],
    "remove": [{ "min": [-1.0, 2.2, 10.5], "max": [1.0, 2.2, 11.0] }],
    "ignore": ["CURTAIN"]
  },
  "type": {
    "doors": {
      "CabD": { "min": [-0.4, 1.909, 9.85], "max": [0.4, 3.9, 9.95], "inner": true },
      "step1": { "min": [1.56, 1.0, 7.6], "max": [1.66, 3.0, 8.31], "fixed": true },
      "DrL_3": { "group": "DrL" },
      "door_9": null
    },
    "cab": { "seats": [
      { "at": [-0.6, 2.75, 10.6] },
      { "at": [0.85, 2.75, 10.7], "yaw": 30 }
    ] }
  }
}
```

**Пол — ключ `"floor"`** (верхний уровень файла, не внутри `"type"`): исключения для генератора, все поля необязательны.
- `"floor": {}` — включить генератор локомотиву или головному вагону (пассажирским он включён всегда); `"floor": false` — выключить;
- `level` — высота пола или список высот (кабина выше салона, ступенька);
- `add` / `remove` — коробки `{min, max}`, которые сделать свободными / занятыми (x и z; y выбирает уровень, если их несколько). `add` применяется до проверки достижимости — так соединяют то, что генератор разорвал (косой проход);
- `ignore` — объекты (имя или регулярное выражение), которые не препятствие;
- `clearance` (0.1), `slab` ([0.3, 1.8] над полом), `step_down` (0.15) — трогай, только если понимаешь зачем, и объясни в отчёте.

**Свой пол — `type.interior`** (список зон `{min, max}`) заменяет сгенерированный целиком. Только если генератор не справляется и исключениями не чинится (тепловоз с мостиками — как у ЧМЭ3). Пол — **объединение** зон (SPEC §9.8): зоны, которые касаются, — один пол, перекрывать их не нужно; щель между ними хоть в 1 см — стена. `min[1]` — высота пола зоны, `max[1]` — потолок (неважен, ставь ~2.5 выше пола).

**Двери — `type.doors` объектом по id:** `{"<id>": {…}}` правит выведенную дверь (меняются только названные поля, `null` у поля его удаляет) или дописывает новую; `{"<id>": null}` удаляет выведенную. Список `"doors": [ … ]` заменяет выведенные целиком, `"doors": []` выключает их — так почти никогда не нужно. Коробка двери — коробка створки, тонкая по нормали стены:
- **без флагов** — наружная, вход и выход;
- **`"inner": true`** — между частями пола: закрытая — стена, открытая — проход;
- **`"connecting": true`** — переход в сцепленный вагон, только в торцевой стене;
- **`"fixed": true`** — проём без створки (подножка): всегда открыт;
- **`"group": "<имя>"`** — двери одной группы открываются вместе (все левые двери электрички).

Двери — и вход генератора: достижимость он считает от наружных дверей, проёмов и переходов. У тепловоза без наружных дверей в модели объяви подножки (`fixed`) — иначе генератор оставит самый большой кусок, и это может быть пустой капот.

**Как дверь двигается на экране** (поле `door_motion` в сводке):
- `anim` — створку двигает IR-анимация группы `CG_<имя>`. Анимация играет, только если у двери `"id": "<имя>"` (регистр неважен) или дверь в одной `"group"` с дверью этого id. Группы с анимациями и их объекты — в `animations`.
- `rot` / `slide` — створку двигает имя (`DOOR_<n>_ROT_<градусы>`, `TL_<f>_<ось>`). Она двигается вместе с дверью, **в коробке которой лежит центр створки** (с запасом 0.1). Бери коробку двери по bbox объектов `DOOR_<n>`.
- `none` — створка нарисована неподвижной. Дверь всё равно проходима.

Клик по двери берёт створку там, где она нарисована сейчас, и не проходит сквозь стены модели (SPEC §9.8).

Состояние открытости в сохранениях держится на **id** двери, порядок дверей неважен. Не переименовывай уже объявленные двери: в старых мирах такая дверь забудет, что была открыта.

**Кресла (`cab.seats`)** — только у локомотивов и головных вагонов. Водительское — каждое кресло списка: машиниста, помощника рядом с ним, кресла кабины на другом конце двухкабинного локомотива, второго поста маневрового.
- `"at": [x, y, z]` — **верх подушки** кресла;
- `"yaw"` — куда оно смотрит, в градусах от +Z (0 — вперёд, по умолчанию; 180 — к пульту задней кабины или второго поста; кресло помощника бывает повёрнуто к пульту на 30–70°). Кресло лицом назад ведёт поезд назад.
- Первым ставь кресло машиниста главной кабины: из занятых кресел одного вагона поездом управляет первое по списку.
- Старая запись одного кресла `"seat": [x, y, z], "seat_yaw": 0` ещё читается, но вместе с `seats` — ошибка.

Ищи кресло по объектам рядом с рычагами (`THROTTLE_n`, `REVERSER_n`, `TRAIN_BRAKE_n`; органы `_2` — второй пост или задняя кабина). Часто это `WIDGET_n` или `SEAT_n`: у ЧМЭ3 — `WIDGET_4`. Кресло помощника обычно стоит зеркально машинистову, но не точно: меряй подушку.

Пол под креслом не нужен: игрок садится с пола в 2.5 от кресла, а встаёт шагами к креслу. `FloorCheck` требует только места, где игрок стоит, в 2.5 от кресла и подушку на 0.2–1.5 выше пола там. Задней кабине нужен свой пол и свой вход (подножки), как у передней.

**Без кресла в ходимой кабине водить нельзя вовсе: машинист — только тот, кто сидит в кресле (клавиши, рычаги мышью и пульт `L`, SPEC §9.7). Если у типа есть кабина и ты включил ему пол — ставь и кресло.**

**Имена:**
- `"name": {"ru_ru": "…"}` — русское имя состава. Английское берётся из IR, его не трогай.
- `"lights": {"<группа>": {"en_us": "…", "ru_ru": "…"}}` — имя каждой группы света из `lights` сводки. Имя короткое (кнопка меню ~30 знаков) и понятное машинисту: «Прожектор передний», «Свет в салоне», «Буферные фонари (зад)», «Подсветка приборов».

## 4. Свет

**Свет размечать не нужно.** Движок берёт его из имён объектов модели, конвенция IR, SPEC §8:
- группа `LCG_<группа>` горит, когда группа включена;
- `FULLBRIGHT` — светится сам;
- `INTERIOR` — деталь салона, её освещают лампы;
- `HEADLIGHT_n` — фара с лучом.

У моделей MVP 1.8 это заполнено полностью — проверено в игре на ЭР2 и ЧМЭ3. Модели MVP 1.7 (`r200*`, `sr3*`, `tep70`, `tgm4`) — один меш без объектов: света в них нет, групп тоже. Напиши это в отчёте и не придумывай им имена.

**Что сделать по каждому своему типу:**
1. **Назвать все группы света** (`"lights"`), на английском и русском. Что значит группа, понятно из:
   - подписей тумблеров (`switches[].label`);
   - где её объекты: фара спереди (z > 0) или сзади, внутри или снаружи (`inside_parts` > 0 — свет салона или кабины);
   - кода (`HL` — прожектор, `BL` — буферные, `RL`/`EL` — хвостовые, `IL`/`CL` — кабина или салон, `PL` — приборы).

   Если смысл неясен, назови по месту («Фонарь над дверью кабины») и отметь в отчёте.
2. **Проверить и записать в отчёт странности**, но не чинить их:
   - группа светит в салоне (`inside_parts` > 0), но у неё нет светящихся объектов — салон будет освещён без видимых ламп;
   - группа без тумблера — её можно включить только с пульта машиниста;
   - тумблер с подписью про свет (`WIDGET_n_..._LABEL_Headlight`) без `CG_` — он ничего не включает.

## 5. Как работать с полом

1. **Посмотри карту генератора** своего типа (из корня репозитория, картинки клади вне репозитория):

   ```
   python -I tools/floorgen.py packs/mvp.json <id> --png /tmp/<id>.png --px 4
   python -I tools/floorgen.py packs/mvp.json <id> --ascii --step 2
   ```

   На карте Z идёт слева направо, X — сверху вниз. Цвета PNG (символы `--ascii`):
   - ярко-зелёный (`o`) — здесь может стоять центр игрока: это и есть то, где он ходит;
   - светло-зелёный (`+`) — пол, на который тело заходит, но центр не встанет (у стен);
   - серо-зелёный (`,`) — свободно, но недостижимо: отброшено;
   - коричневый (`#`) — препятствие над полом; серый (`.`) — пол, но не свободный; чёрный — пола нет;
   - оранжевый (`D`) — наружная дверь, пурпурный (`G`) — переход, жёлтый (`i`) — внутренняя дверь.

   Генератор работает на любом типе, даже без `"floor"` в файле, — так смотрят локомотив до того, как включить ему пол. Для пола, размеченного вручную, `--compare` красит красным то, что есть только у ручного, синим — только у генератора.
2. **Проверь по карте**:
   - проход по вагону непрерывный, ярко-зелёная полоса нигде не рвётся;
   - тамбуры и кабина соединены с салоном внутренними дверями (жёлтое между двумя зелёными частями);
   - к каждой наружной двери и переходу подходит пол;
   - нет «пола» там, где ходить нельзя: внутри капота, под рамой, в шкафу, на полках;
   - кабина — пол, место у пульта, проход к креслу.
3. **Почини исключениями** (`"floor"`): лишнее — `remove`; разорванный проход — `add`; объект, который зря мешает, — `ignore`; не тот уровень или несколько уровней — `level`. Перегенерируй карту и сравни.
4. **Если исключения не помогают** — свой `type.interior`, как у ЧМЭ3, и объясни в отчёте, что генератор делал не так.
5. **Кресло**: объект кресла (подушка) — верх его bbox по Y. По модели напрямую: `python -I tools/objinfo.py <id> [--controls] [--grep RE] [--floors --x a b --z a b] [--doors] [--lights]` (Python 3.9+, только stdlib).

## 6. Правила (так их прочтёт движок; первые шесть проверяет `FloorCheck`)

1. Пол — объединение зон. Центр игрока держится в **0.3** от его края: игрок стоит там, где квадрат 0.6 × 0.6 целиком на полу. Место уже 0.6 непроходимо; зона, в которой игрок не помещается нигде, — ошибка (если она не расширяет соседнюю).
2. Части пола, между которыми надо ходить, должны **касаться** (или перекрываться). Между частями, которые разделяет стена, оставь щель; если в стене дверь — внутренняя дверь: её коробка — между частями, мостик тянется на 0.6 за каждую грань двери.
3. Наружная, переходная дверь или проём — **там, где кончается пол**: перед дверью, в пределах её пролёта, игрок помещается, а пол, если идти прямо к двери, кончается не дальше **0.4** от её внутренней грани. Иначе сквозь неё не выйти.
4. Переходная дверь — в **торцевой** стене: её коробка тоньше по Z, чем по X. Пол у торца должен доходить до неё.
5. Кресло — над полом, верх подушки на **0.2…1.5** выше пола зоны.
6. Ось двери определяется по тонкой стороне коробки, «наружу» — по знаку её центра. Коробка двери толще 0.6 — подозрительно.
7. Створка `rot`/`slide` — центром в коробке своей двери; створка `anim` — у двери с id её группы или в её `"group"`.
8. `"lights"` называет только группы, которые есть в модели.

## 7. Как проверять

- Сборка и тесты: `./gradlew test`. Нужен JDK 21 и сеть: первая сборка качает Minecraft и NeoForge. Если сборка не смогла скачать зависимости, напиши об этом в отчёте и не обходи проблему.
- `RecipeFloorTest` собирает каждый тип из сводки и твоего файла и прогоняет `FloorCheck`. `RecipeDoorsAndLightsTest` проверяет правила 7–8. Каждый тип — отдельный тест с полным списком ошибок. **Все твои типы должны быть зелёными.** Остальные тесты не ломай.
- Проверка на настоящем паке:
  1. Перегенерируй пак и сводки: `python -I tools/ir2rwat.py packs/mvp.json --geometry packs/mvp/geometry` (около двух минут; не из папки пака). Конвертер предупредит о группе света, которой нет в модели, и о том, что генератор не смог (`no generated floor — …`, например неизвестный ключ в `"floor"`): тогда пассажирский вагон получает прежнюю коробку из IR-зоны.
  2. Запусти тесты: `PackFloorTest` проверит твои типы в сгенерированном паке, `RecipeFloorTest` — сводки.
  3. **Перед коммитом верни сгенерированное:** `git restore run/rwat_packs packs/mvp/geometry` (и удали новые папки `anim/`, если перегенерация их создала). Пак после слияния всех групп перегенерируют один раз.
- `RecipeFloorTest` берёт сгенерированный пол из закоммиченной сводки. Если ты включил генератор локомотиву (`"floor"`) и поставил кресло или поменял исключения, тест твоего типа на закоммиченном состоянии красный, пока сводки не перегенерированы (`cab.seats without an interior`, `can't be walked to`). Это ожидаемо: решает зелёный прогон на перегенерированном паке (шаг 2). Напиши в отчёте, какие типы так красны.
- Логику ходьбы и переходов смотри в тестах `FloorUnionTest`, `GangwayTest`, `CabFloorTest`.

### Посмотреть в игре (по желанию)

В облаке игра запускается под виртуальным экраном (Xvfb, программный рендер Mesa, без звука). Полный рецепт — SPEC §9.7, «Как запустить игру в облаке». Коротко:

1. Мир: `./gradlew runServer` с `run/server/eula.txt` (`eula=true`) и `level-type=minecraft\:flat` в `run/server/server.properties`. После строки `Done` в `run/server/logs/latest.log` останови сервер сигналом SIGTERM (он сохранит мир) и скопируй `run/server/world` в `run/saves/<имя>`, удалив `session.lock`.
2. В `run/options.txt` — `pauseOnLostFocus:false` и `onboardAccessibility:false`, иначе сцену закроет пауза или экран доступности.
3. Клиент: `xvfb-run -a -s "-screen 0 1920x1080x24" ./gradlew runClient -PquickPlay=<имя> -Pautoscene=<сцена>`. Снимки — в `run/screenshots/`, что делал игрок — в логе, строки `[autoscene]`.

Готовые автосцены (`debug.ClientAutoScene`): `walkgen` — ЭР2 и `walkgen-dr1` — ДР1 на сгенерированном полу (клик по боковой двери с земли, посадка, клик по двери тамбура, проход по салону с замером шага на каждом тике, каркасы пола), `doorclick` — клики по дверям плацкарта, `gangway` — переход между плацкартами, `cab` и `walk` — ЧМЭ3, `er2` — свет ЭР2, `panel` — пульт ЧС4Т. Для своего типа проще всего **временно** добавить запись `WalkCar` по образцу `ER2`/`DR1` (что поставить, боковая дверь, дверь тамбура, где остановиться) и своё имя сцены рядом с `walkgen-dr1`, но **не коммить это** (раздел 9). Что увидел на снимках и в логе — в отчёт (раздел 10).

## 8. Распределение работы (по агенту на группу, каждый правит только свои файлы)

У всех групп, по каждому типу: `"name"` (русское имя) и `"lights"` (имена всех групп света, раздел 4).

| Группа | Типы | Что сделать ещё |
|---|---|---|
| B. Моторвагонные и дизель-поезда | `er2m`, `er2m_reversed`, `er2t`, `dr1a_trailed`, `bmz_diesel`, `r200c`, `r200m`, `sr3m` | Пол уже строит генератор (у ЭР2 и ДР1 проверено в игре, SPEC §9.8). Посмотри карту каждого типа (раздел 5), почини исключениями то, что не так. У `bmz_diesel` в файле стоит временная заглушка пола одной коробкой — убери её (`"interior": null` в `type` или удали ключ) и доведи сгенерированный пол до зелёного `FloorCheck`. У `r200*` и `sr3m` в модели нет объектов (один меш): дверей нет, вход остаётся по ПКМ, генератор берёт самый большой кусок — проверь, что это салон. |
| C. Локомотивы с кабинами | `tem2`, `tem2y`, `tgm23`, `tgm4`, `m62`, `chs4t`, `dgku`, `tep70`, `2te116`, `vl80c` | Пол кабины (+ мостики и площадки, где есть, как у ЧМЭ3), двери кабины (внутренние, если выходят на мостик; наружные, если сразу наружу), подножки-проёмы (`fixed`), **кресло**. Начни с карты без `"floor"`: у ТЭМ2 генератор находит настил 2.311, но без наружных дверей оставляет пустой капот — объяви подножки, и он пойдёт от них. Если исключениями не выходит — ручной `interior`, как у ЧМЭ3. У `dgku` и `tgm23` двери на шарнире (`rot`) — коробка по `DOOR_n`. Переходы между секциями (`2te116`, `vl80c`), если есть пол по обе стороны. |
| D. Головные вагоны | `er2h`, `er2h_reversed`, `dr1a_motorhead`, `dr1a_motorhead_reversed`, `r200h`, `sr3h` | `"floor": {}` — салон и тамбуры даёт генератор (у `er2h` проверено картой). Кабина: обычно другой уровень (`level` списком) или отдельная часть — соедини её с тамбуром дверью кабины (внутренняя) или `add`; **кресло**. С полом двери выведутся из модели — проверь их. |

Плацкарт (`amendorf`, `amendorf_baggage`) и ЧМЭ3 не трогай: их пол ручной, менять его на генератор решает пользователь. Грузовые (`freight`, `tank`) не трогай.

## 9. Чего не делать

- Не меняй Java-код, конвертер и генератор (`tools/`), SPEC и чужие файлы `packs/mvp/*.json`. Нашёл ошибку движка или генератора — опиши её в отчёте (что на карте, где, почему это неправильно).
- Не коммить сгенерированный пак, сводки, zip и картинки карт (`run/`, `packs/mvp/geometry`, `MVP-*.zip`, `*.png`). Ассеты не меняй.
- Не переименовывай уже объявленные двери: id в сохранениях.

## 10. Что сдать

Ветку с изменёнными `packs/mvp/<id>.json` твоей группы, зелёный `./gradlew test` и отчёт в описании PR. В отчёте по каждому типу:
1. **Пол:** что показала карта генератора (проход, тамбуры, кабина, лишнее), какие исключения поставил и зачем; если ручной `interior` — почему генератор не справился.
2. **Двери и кресло:** что дописал или поправил по id, откуда числа (объекты, уровни пола).
3. **Свет:** таблица «группа → имя → почему так», странности из раздела 4.
4. **Что проверить в игре:** если снимал игру в облаке — что видно на снимках и в логе сцены; командой `/rwatc floors` (каркасы: зелёный — зоны пола, ярко-зелёный у пола — где может стоять центр игрока, голубой — наружная дверь, жёлтый — внутренняя, пурпурный — переходная, серый — проём, красный — кресло). Укажи места, в которых не уверен.
5. **Чего не хватает в движке или генераторе**, если что-то нельзя выразить разметкой. Пример: тумблер дверей в кабине ЭР2 (`CG_DrL_GLOBAL`) пока не открывает двери.
