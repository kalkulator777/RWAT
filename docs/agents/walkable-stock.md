# Разметка состава MVP — инструкция для агента

Ты размечаешь подвижной состав пака MVP (Matoi Vanilla Pack) для мода RWAT (Minecraft 1.21.1, NeoForge). Что нужно сделать:
- **пол** — по чему ходит игрок;
- **двери** — вход и выход, переходы между вагонами, двери между частями вагона;
- **кресло машиниста** у локомотивов и головных вагонов;
- **имена** — русское имя состава и имена групп света для меню машиниста.

Игры в облаке нет. Ты меряешь по сводкам геометрии и моделям, проверяешь тестами, а в игре результат потом смотрит человек.

Ответы и отчёт — на русском (проект ведётся на русском).

## 2. Как это устроено

**Что лежит в репозитории.** Всё, что нужно для работы, — временно, это сторонний контент под CC BY-NC-ND 4.0:
- `MVP-IR-*.zip` в корне — исходные паки IR;
- `run/rwat_packs/MatoiVanillaPack/` — сгенерированный пак: модели OBJ, текстуры, декларации;
- `packs/mvp/geometry/<id>.json` — сводки геометрии (только числа).

**Где ты работаешь.**
- Пак **генерируется** конвертером `tools/ir2rwat.py` из zip.
- Ручные данные лежат в `packs/mvp/<id>.json`, по файлу на тип. Конвертер накладывает их поверх выведенного: deep merge, `null` удаляет поле.
- **Ты правишь только эти файлы.**

**Что конвертер выводит сам:**
- **пассажирским вагонам** — пол одной коробкой из IR-зоны пассажиров;
- **типам, у которых есть пол**, — двери из объектов модели `DOOR_<n>`:
  - `EXTERNAL` — наружные, вход и выход;
  - `CONNECTING` — переход в соседний вагон;
  - остальные — внутренние.

  Две створки одного проёма становятся одной дверью. Проёмы на одной группе `CG_` получают общий `"group"` и открываются вместе.

Свои `interior` или `doors` в файле **заменяют** выведенное целиком. `"doors": []` выключает выведенные двери.

**Что выведенного обычно не хватает:**
- Пол-коробка грубая: в плацкарте игрок идёт по центру вагона сквозь полки, а не по коридору.
- У локомотивов и головных вагонов нет ни пола, ни кресла. Как только ты задашь `interior`, двери выведутся из модели сами — ровно `doors_in_model` сводки.
- Нет имён групп света. У ДР1 и ВЛ80 в меню видны коды «CCL», «HBL».
- Нет русских имён состава.

**Сводки геометрии `packs/mvp/geometry/<id>.json`** — твои глаза:
- `objects` — bbox каждого объекта модели;
- `floor_levels` — горизонтальные поверхности по высоте, с площадью и габаритом в плане;
- `ir_passenger` — IR-зона пассажиров;
- `derived` — что выведет конвертер;
- `doors_in_model` — все двери модели, как их выведет конвертер;
- `door_motion` — как движется створка каждой `DOOR_<n>` (раздел 3);
- `animations` — группы IR-анимаций и объекты, которые они двигают;
- `lights` — группы света: светящиеся объекты (`glowing`), фары (`headlights`), сколько деталей салона светит (`inside_parts`), тумблеры с подписями (`switches`).

**Если чего-то из этого нет — остановись и напиши об этом в отчёте.**

### Система координат (модель RWAT = файл типа)

- +Z — вперёд по ходу (у IR перёд −X, сводки уже переведены);
- X — поперёк, Y — вверх;
- головка рельса — y 0.406, пол пассажирских вагонов MVP — около 1.81, настил ЧМЭ3 — 2.311;
- середина вагона — z = 0, концы — ±длина/2.

## 3. Формат файла `packs/mvp/<id>.json`

```json
{
  "name": {"ru_ru": "ЭР2, моторный вагон"},
  "lights": {
    "ER2L": {"en_us": "Saloon light", "ru_ru": "Свет в салоне"}
  },
  "type": {
    "interior": [
      { "min": [-1.35, 1.81, -11.75], "max": [1.35, 4.5, -10.4] },
      { "min": [0.55, 1.81, -11.0],   "max": [1.35, 4.5, 11.0] }
    ],
    "doors": [
      { "id": "Door1", "min": [1.362, 1.811, 10.875], "max": [1.638, 3.811, 11.688] },
      { "id": "DoorTambur", "min": [0.5, 1.81, 10.3], "max": [1.4, 3.8, 10.4], "inner": true },
      { "id": "Trap1", "min": [-0.438, 1.936, 11.75], "max": [0.438, 3.874, 12.044], "connecting": true },
      { "id": "step1", "min": [1.56, 1.0, 7.6], "max": [1.66, 3.0, 8.31], "fixed": true },
      { "id": "DrL_3", "min": [1.677, 1.471, -9.425], "max": [1.756, 3.915, -8.15], "group": "DrL" }
    ],
    "cab": { "seat": [-1.062, 3.092, -4.654], "seat_yaw": 0.0 }
  }
}
```

**Пол (`interior`)** — список прямоугольных зон (одна зона — можно объектом). `min[1]` — высота пола зоны, `max[1]` — потолок (неважен, ставь ~2.5 выше пола).

**Двери (`doors`)** — коробка створки, тонкая по нормали стены:
- **без флагов** — наружная, вход и выход;
- **`"inner": true`** — между зонами пола: закрытая — стена, открытая — проход;
- **`"connecting": true`** — переход в сцепленный вагон, только в торцевой стене;
- **`"fixed": true`** — проём без створки (подножка): всегда открыт;
- **`"group": "<имя>"`** — двери одной группы открываются вместе (все левые двери электрички).

**Как дверь двигается на экране** (поле `door_motion` в сводке):
- `anim` — створку двигает IR-анимация группы `CG_<имя>`. Анимация играет, только если у двери `"id": "<имя>"` (регистр неважен) или дверь в одной `"group"` с дверью этого id. Группы с анимациями и их объекты — в `animations`. Например, у плацкарта `WIDGET_3_..._CG_DoorTambur` → `"id": "DoorTambur"`.
- `rot` / `slide` — створку двигает имя (`DOOR_<n>_ROT_<градусы>`, `TL_<f>_<ось>`). Она двигается вместе с дверью, **в коробке которой лежит центр створки** (с запасом 0.1). Бери коробку двери по bbox объектов `DOOR_<n>`.
- `none` — створка нарисована неподвижной. Дверь всё равно проходима.

Порядок дверей — их индекс: на нём держится состояние открытости в сохранениях. **Не переставляй уже объявленные двери, дописывай новые в конец.** Выведенные двери идут по номеру `DOOR_<n>`. Если берёшь их за основу, сохраняй этот порядок.

**Кресло (`cab.seat`)** — только у локомотивов и головных вагонов:
- `[x, y, z]` — **верх подушки** кресла;
- `seat_yaw` — куда оно смотрит, в градусах от +Z (обычно 0 или 180 — к пульту).

Ищи кресло по объектам рядом с рычагами (`THROTTLE_n`, `REVERSER_n`, `TRAIN_BRAKE_n`). Часто это `WIDGET_n` или `SEAT_n`: у ЧМЭ3 — `WIDGET_4`.

**Без кресла машинист в ходимой кабине не может водить клавишами. Ставь пол кабины только вместе с креслом.**

**Имена:**
- `"name": {"ru_ru": "…"}` — русское имя состава. Английское берётся из IR, его не трогай.
- `"lights": {"<группа>": {"en_us": "…", "ru_ru": "…"}}` — имя каждой группы света из `lights` сводки. Имя короткое (кнопка меню ~30 знаков) и понятное машинисту: «Прожектор передний», «Свет в салоне», «Буферные фонари (зад)», «Подсветка приборов».

## 4. Свет

**Свет размечать не нужно.** Движок берёт его из имён объектов модели, конвенция IR, SPEC §8:
- группа `LCG_<группа>` горит, когда группа включена;
- `FULLBRIGHT` — светится сам;
- `INTERIOR` — деталь салона, её освещают лампы;
- `HEADLIGHT_n` — фара с лучом.

У моделей MVP 1.8 это заполнено полностью — проверено в игре на ЭР2 и ЧМЭ3. Модели MVP 1.7 (`r200*`, `sr3*`, `tep70`, `tgm4`) — один меш без объектов: света в них нет, групп тоже. Напиши это в отчёте и не придумывай им имена.

**Что сделать по каждому своему типу:**
1. **Назвать все группы света** (`"lights"`), на английском и русском. Что значит группа, понятно из:
   - подписей тумблеров (`switches[].label`);
   - где её объекты: фара спереди (z > 0) или сзади, внутри или снаружи (`inside_parts` > 0 — свет салона или кабины);
   - кода (`HL` — прожектор, `BL` — буферные, `RL`/`EL` — хвостовые, `IL`/`CL` — кабина или салон, `PL` — приборы).

   Если смысл неясен, назови по месту («Фонарь над дверью кабины») и отметь в отчёте.
2. **Проверить и записать в отчёт странности**, но не чинить их:
   - группа светит в салоне (`inside_parts` > 0), но у неё нет светящихся объектов — салон будет освещён без видимых ламп;
   - группа без тумблера — её можно включить только из меню машиниста;
   - тумблер с подписью про свет (`WIDGET_n_..._LABEL_Headlight`) без `CG_` — он ничего не включает.

## 5. Как мерить

1. Пол: в `floor_levels` найди большие площади на одной высоте внутри корпуса — это пол. Ступенька ниже — тамбур, выше — кабина или полки. Например, у плацкарта пол 1.81 (69 м²), нижние полки 2.44, верхние 4.06.
2. Стены, перегородки, коридор — по bbox объектов:
   - `INTERIOR*` — салон;
   - `DOOR_*`, `WIDGET_*` — двери;
   - полки и перегородки — по их габаритам в `objects`.

   Зоны делай по проходимым местам: тамбуры во всю ширину, коридор вдоль стенки, кабина, мостики.
3. Двери: возьми из `doors_in_model` или по bbox объектов `DOOR_<n>` / `WIDGET_<n>`.
4. Кресло: объект кресла (подушка) — верх его bbox по Y.
5. По модели напрямую: `python tools/objinfo.py <id> [--controls] [--grep RE] [--floors --x a b --z a b] [--doors] [--lights]` (Python 3.9+, только stdlib).

## 6. Правила (так их прочтёт движок; первые шесть проверяет `FloorCheck`)

1. Центр игрока держится в **0.3** от стен зоны. Зона уже 0.6 по любой оси — непроходима.
2. Соседние зоны, между которыми надо ходить, **перекрываются ≥ 0.6**. Иначе соедини их внутренней дверью: её коробка — между зонами, мостик тянется на 0.6 за каждую грань двери.
3. Наружная, переходная дверь или проём — **в стене зоны**:
   - внутренняя грань двери лежит не дальше **0.6** от стороны зоны с той стороны;
   - пролёт двери пересекается с зоной вдоль стены.

   Иначе сквозь неё не выйти.
4. Переходная дверь — в **торцевой** стене: её коробка тоньше по Z, чем по X. Зона у торца должна доходить до неё.
5. Кресло — над зоной пола, верх подушки на **0.2…1.5** выше пола зоны.
6. Ось двери определяется по тонкой стороне коробки, «наружу» — по знаку её центра. Коробка двери толще 0.6 — подозрительно.
7. Створка `rot`/`slide` — центром в коробке своей двери; створка `anim` — у двери с id её группы или в её `"group"`.
8. `"lights"` называет только группы, которые есть в модели.

## 7. Как проверять

- Сборка и тесты: `./gradlew test`. Нужен JDK 21 и сеть: первая сборка качает Minecraft и NeoForge. Если сборка не смогла скачать зависимости, напиши об этом в отчёте и не обходи проблему.
- `RecipeFloorTest` собирает каждый тип из сводки и твоего файла и прогоняет `FloorCheck`. `RecipeDoorsAndLightsTest` проверяет правила 7–8. Каждый тип — отдельный тест с полным списком ошибок. **Все твои типы должны быть зелёными.** Остальные тесты не ломай.
- Проверка на настоящем паке:
  1. Перегенерируй пак: `python tools/ir2rwat.py packs/mvp.json --geometry packs/mvp/geometry`. Конвертер предупредит о группе света, которой нет в модели.
  2. Запусти тесты: `PackFloorTest` проверит твои типы в сгенерированном паке.
  3. **Перед коммитом верни сгенерированное:** `git restore run/rwat_packs packs/mvp/geometry`. Пак после слияния всех групп перегенерируют один раз.
- Логику переходов и ходьбы смотри в тестах `GangwayTest` и `CabFloorTest`: там видно, как шаг идёт по зонам.

## 8. Распределение работы (по агенту на группу, каждый правит только свои файлы)

У всех групп, по каждому типу: `"name"` (русское имя) и `"lights"` (имена всех групп света, раздел 4).

| Группа | Типы | Что сделать ещё |
|---|---|---|
| A. Плацкарт | `amendorf`, `amendorf_baggage` | Пол из зон: тамбуры во всю ширину у концов, коридор вдоль стенки, купе-отсеки по желанию. Внутренние двери: тамбурные (`DoorTambur`), туалет (`DoorToilet`), служебное купе (`DoorKupe`). Это `WIDGET_n` с IR-анимацией, id — по `CG_`. Боковые и переходные уже выведены — проверь, что они в стенах зон. Убрать временную заглушку пола у `amendorf_baggage`. У `amendorf` имена уже есть — проверь их. |
| B. Моторвагонные и дизель-поезда | `er2m`, `er2m_reversed`, `er2t`, `dr1a_trailed`, `bmz_diesel`, `r200c`, `r200m`, `sr3m` | Тамбуры и салон зонами. ## 9. Чего не делать

- Не меняй Java-код, конвертер, SPEC и чужие файлы `packs/mvp/*.json`. Нашёл ошибку движка — опиши её в отчёте.
- Не коммить сгенерированный пак, сводки и zip (`run/`, `packs/mvp/geometry`, `MVP-*.zip`). Ассеты не меняй.
- Не переставляй уже объявленные двери: индексы в сохранениях.

## 10. Что сдать

Ветку с изменёнными `packs/mvp/<id>.json` твоей группы, зелёный `./gradlew test` и отчёт в описании PR. В отчёте по каждому типу:
1. **Что размечено:** зоны словами («тамбур передний, коридор по +X…»), двери, кресло.
2. **Откуда числа:** какие объекты и уровни пола.
3. **Свет:** таблица «группа → имя → почему так», странности из раздела 4.
4. **Что проверить в игре:** командой `/rwatc floors` (каркасы: зелёный — пол, голубой — наружная дверь, жёлтый — внутренняя, пурпурный — переходная, серый — проём, красный — кресло). Укажи места, в которых не уверен.
5. **Чего не хватает в движке**, если что-то нельзя выразить разметкой. Пример: тумблер дверей в кабине ЭР2 (`CG_DrL_GLOBAL`) пока не открывает двери.
