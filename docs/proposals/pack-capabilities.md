# Возможности паков: что пак может задать и где кончается движок

**Аудит 2026-10-31.** Основа для веб-редактора паков: редактор должен покрывать всё, что умеет пак, и не больше. Собрано по коду, не по SPEC: SPEC местами устарел (расхождения — §14). Пути Java — от `src/main/java/com/muzhik17/trainsmod/`.

Каждая возможность помечена:
- **пак** — задаётся паком явно (поле JSON или имя объекта в OBJ);
- **сам** — движок выводит автоматически;
- **зашито** — константа или допущение в коде;
- **нет** — не поддерживается.

---

## 0. Коротко

**Что пак умеет сейчас:**
- вагон на двух тележках с полной продольной физикой;
- ходимый салон из плоских зон пола на разных высотах;
- двери: наружные, переходные, внутренние, проёмы;
- кабины с несколькими креслами;
- органы управления и приборы по конвенции IR;
- свет: салон, фары, светящиеся детали;
- звуки, ливреи, стили рельсов;
- конвертация IR-паков.

**Чего пак не может, потому что этого нет в движке:**
- **двухэтажный вагон**: пол двумерный, под этажом этаж не выразить;
- **сочленённые составы и постоянная сцепка**: любой сцеп расцепляется монтировкой, тележек Якобса нет;
- **паровоз**: нет ведущих колёс, дышел и парораспределения, нет физики пара; тендер — отдельный вагон;
- **колея**: одна, зашита; высота рельса зашита;
- **корпус** — одна коробка 3.4 × 4.3 у всех вагонов: широкие, высокие и открытые кузова не по модели;
- **анимации кроме дверей**: токоприёмники, дворники, окна только как жёсткие органы с одной осью;
- **места пассажиров, груз, полупрозрачные стёкла**;
- **контент кроме состава и рельсов**: сигналы, контактная сеть, блоки, предметы.

**Вывод:** формат покрывает «вагон или локомотив обычной схемы». Чтобы редактор покрывал больше, сначала нужно расширять движок. План по приоритетам — в §15.

## 1. Из чего состоит пак

Пак — обычный пак Minecraft, один каталог или zip одновременно ресурс-пак и датапак (`pack/RwatPacks.java`). Мод читает **только три папки** и файлы, на которые они ссылаются:

| Папка | Сторона | Что |
|---|---|---|
| `data/<ns>/wagon_types/<id>.json` | сервер, синк клиенту | тип вагона: геометрия, физика, пол, двери, кабина (§3) |
| `assets/<ns>/wagon_models/<id>.json` | клиент | модель того же id: OBJ, анимации, ливреи, звуки (§4) |
| `assets/<ns>/rail_models/<id>.json` | клиент и сервер | стиль рельсов (§9) |

Плюс lang-файлы (§10) и любые ассеты: OBJ, MTL, PNG, `.anim`, `.ogg`.

- id = `<ns>:<путь файла>`. Тип и модель связаны только совпадением id.
- `pack.mcmeta` обязателен (пак без него пропускается); блок `"rwat"` в нём мод не читает.
- **Своей версии формата нет.**
- Незнакомые ключи везде **молча игнорируются**, опечатка (`mass` вместо `mass_t`) не ловится.
- Ошибка в любом поле выбрасывает весь файл. Видно это только в логе.

## 2. Системы координат

- **OBJ модели (конвенция IR):** 1 единица = 1 блок, Y вверх, ось хода X, **перёд — −X**.
  - Низ круга катания колеса должен стоять на y = −0.03 (ось колеса на 0.5, радиус 0.53, `IrStockModel.java:73-85`).
- **Разметка в JSON типа** (пол, двери, кресла): кадр модели RWAT.
  - +Z вперёд, X поперёк (+X — левый борт по ходу), Y вверх.
  - Начало — центр кузова; y = 0 — сплайн пути, головка рельса на +0.40625.
  - Пересчёт из OBJ: `x = z_obj`, `y = y_obj + 0.43625`, `z = −x_obj`.
  - Всё выровнено по осям, повёрнутых коробок нет.
- **OBJ тайла рельса:** рельсы вдоль X, тайл центрирован на x = 0, колея по Z.

Автор, который снимает координаты в Blender, получает другие числа, чем пишет в JSON. Редактор должен прятать это полностью.

## 3. Тип вагона — `data/<ns>/wagon_types/<id>.json`

Парсер: `stock/WagonTypeParser.java`. Умолчания: `stock/StockDefaults.java`.

**Правила:**
- пропущенное поле = значение движка, явный `0` = ноль;
- **JSON `null` роняет файл** (допустим только в `doors[].group`) — редактор не должен его писать.

| Ключ | Тип, единицы | По умолчанию | Примечание |
|---|---|---|---|
| `length` | блоки (= м), по сцепкам | **обязателен** | не валидируется (0 и минус пройдут) |
| `bogies` | массив, блоки от центра, +вперёд, передний первым | **обязателен** | ≥ 1 элемента; **работают только первый и последний** (§12) |
| `mass_t` | т | **обязателен** | > 0 |
| `max_speed_kmh` | км/ч | нет = не ограничивает | шкала спидометра (без него — 100/200), губернатор тяги |
| `resistance.a` / `b` / `c` / `c_front` | Н; Н·с/м; Н·с²/м² | `7·m + 200` / `14` / `1.3` / `5` | каждое подполе отдельно; `c_front` платит только головной вагон |
| `traction.power_kw`, `traction.max_tractive_effort_kn` | кВт, кН | секции нет = не тянет | оба обязательны, если секция есть |
| `traction.adhesion`, `traction.ramp_s` | множитель; с | `1.0`, `4.0` | `0` обнуляет тягу |
| `brakes.system` | `passenger` \| `freight` \| `ep` | `passenger` | пресеты: 1.0 кН/т, 4/8 с · 0.6 кН/т, 15/30 с · 1.1 кН/т, 1.5/3 с |
| `brakes.train_kn` | кН | кН/т(system) · m | автотормоз, все вагоны |
| `brakes.independent_kn` | кН | `0.7·m`, только при `cab` | действует на **все** вагоны с `cab` |
| `brakes.parking_kn` | кН | `0.4·m` | ручник |
| `brakes.apply_s`, `brakes.release_s` | с | из пресета | поезд берёт максимум по вагонам |
| `brakes.dynamic_kn`, `brakes.dynamic_fade_kmh` | кН, км/ч | 0 | **парсятся, в физике не используются** |
| `cab` | объект, можно `{}` | нет = управлять нельзя | см. ниже |
| `cab.seats[]` | `{at: [x,y,z], yaw}` | — | ≤ 16; `at` — верх подушки; `yaw` 0 = вперёд; > 90° от «вперёд» — ведёт назад; legacy `seat` + `seat_yaw` |
| `interior` | `{min, max}` или массив | нет = неходим | **только коробки**; работают план и `min.y`, `max.y` не используется (§7) |
| `doors[]` | `{id, min, max, inner?, fixed?, connecting?, group?}` | `[]` | порядок = индекс; работают ≤ 32 двери (§7) |
| `couplers.front` / `rear` | блоки от торца, + наружу | 0 / 0 | любые числа |
| `aliases` | старые id | `[]` | только сервер, один уровень |

**Сам:**
- роли: «тянет» = есть `traction`, «управляется» = `cab`, «ходим» = `interior`;
- корпус коллизии из `length`;
- поза кузова по двум тележкам;
- кабины внутри типа и «кабинные» двери — из пола и кресел (`kinematics/CabArea.java`);
- зеркалирование развёрнутого вагона;
- предупреждения `FloorCheck` в лог.

**Нет на уровне типа:**
- колея;
- тип, высота и совместимость сцепок, конец без сцепки;
- постоянная сцепка или «единица из N вагонов»;
- топливо, вода, котёл, токоприёмник;
- правила MU;
- груз;
- форма корпуса;
- доступ к кабине — он глобальный, `[access] cab_access` сервера;
- ливреи — это данные модели.

**Физика без выбора:**
- дизель, электро и пар не различаются;
- тяга — гипербола `min(TE, P/v)` с потолком по сцеплению;
- 8 позиций контроллера на всё;
- тянут все тяговые вагоны состава, рукоятки одни на состав.

## 4. Модель — `assets/<ns>/wagon_models/<id>.json`

Парсер: `client/render/model/WagonModelDecl.java`.

| Ключ | Тип | По умолчанию | Что делает |
|---|---|---|---|
| `obj` | путь (ResourceLocation) | **обязателен** | без `ns:` — неймспейс пака; невалидный путь или файла нет — рисуется коробка |
| `bogies` | массив | центры мешей `BOGEY_FRONT*`/`BOGEY_REAR*` | пивоты тележек **в OBJ**, только для перецентровки мешей; по пути их ведут `bogies` типа |
| `skip` | префиксы имён | `[]` | не рисовать (регистр важен); `CARGO_FILL*` и `*HIDE*` — всегда |
| `animations` | `{группа: путь .anim}` | `{}` | группа = `id` двери типа без учёта регистра; **анимируются только двери** |
| `liveries` | `{id: папка}` | `{}` | папка рядом с OBJ; текстура с тем же именем файла заменяет базовую; имя ливреи не переводится |
| `handbrake` | ключи органов | `[]` | орган становится маховиком ручника (`WIDGET_13`) |
| `sounds` | объект | — | §8 |
| `sway` | 0…3 | 1 | сила тряски кузова поверх настройки игрока |

**Файлы, на которые ссылается модель:**
- **OBJ** (`ObjLoader.java`):
  - читаются `v/vt/vn/f/usemtl/mtllib/o/g`;
  - имя объекта — первый токен строки (пробел обрезает имя);
  - индексы только положительные: отрицательный ломает модель;
  - n-угольники режутся веером;
  - без нормали — (0,1,0), без UV — (0,0); цвет вершин игнорируется.
- **MTL** (`MtlParser.java`):
  - только `newmtl` и `map_Kd`;
  - материал без `map_Kd` **не рисуется** и не загораживает клики;
  - путь текстуры — относительно OBJ и только в неймспейсе OBJ;
  - `d/Tr/Ke/bump` игнорируются.
- **Рендер:** только cutout (`entityCutoutNoCull`), полупрозрачности нет, эмиссивных карт нет.
- **LOD:** только `INTERIOR*` прячется дальше `interiorDrawDistance`.
- Бюджет полигонов не зашит; ориентир из комментариев — ~17k квадов на вагон. Каждая пара «деталь × текстура» — отдельный draw call.
- **`.anim`** (`IrAnim.java`):
  - строки `O <объект>` и `M` с 16 числами (матрица относительно покоя);
  - объекты сопоставляются по точному имени;
  - кадр = прогресс двери × (N−1), матрицы интерполируются линейно;
  - ход двери всегда **40 тиков** (зашито).

## 5. Имена объектов OBJ

Регистр важен. Суффикс Blender `.NNN` отбрасывается при разборе роли (`convention/ObjectRole.java`). Флаг засчитывается как `_T_`, `T_` в начале, `_T` в конце или всё имя. Всё незнакомое — жёсткий кузов, так что статика может называться как угодно. **Функции же требуют имён IR.** Своё имя RWAT ровно одно — `HANDBRAKE_<n>`.

**Порядок разбора** (`IrStockModel.java:328-417`): `HIDE`/`skip` → голова сцепки → тележка или колесо → объект из `.anim` → створка двери → орган → без текстуры выбросить → `INTERIOR*` или кузов. Признаки света навешиваются на любой текстурированный объект.

**Геометрия**

| Имя | Что делает |
|---|---|
| `BOGEY_FRONT*` / `BOGEY_REAR*` | рама тележки, поворачивается по касательной пути |
| …+ `_WHEEL_` | колёсная пара, крутится вокруг X; **радиус 0.53 у всех**; каждый объект — пара |
| `INTERIOR*` (префикс) | интерьер: прячется по дальности |
| `INTERIOR` (токен) | квад освещается лампами салона; группа с таким объектом — свет салона |
| `*HIDE*` (подстрока) | выбрасывается при загрузке (кроме `WIDGET` и `COUPLED_*`) |
| `CARGO_FILL*` | выбрасывается всегда |
| `COUPLED_FRONT_<n>` / `COUPLED_REAR_<n>` | голова сцепки: с `HIDE` — видна расцепленной, с `HIDE` + `INVERT` — сцепленной; поворачивается к соседу ≤ 22° |
| `FRAME_WHEEL_*`, `SIDE_ROD_*`, `WIPER*`, `DIESEL_EXHAUST*`, `COUPLER_ENGAGED_*`, `SEAT_*` | **статика** (у IR они живые) |

**Двери в модели**
- Объекты из `.anim` группы двери двигаются по её кадрам.
- `DOOR_<n>` с маркером `DOOR_<n>_ROT[_град]` или `TL_<f>_<X|Y|Z>` — жёсткая створка. Её ведёт та дверь типа, в коробке которой (±0.1) лежит центр створки. `INVERT` и `OFFSET` у створок не работают.
- `EXTERNAL` / `CONNECTING` / `INTERNAL` движок **не читает**: по ним конвертер выводит двери типа.

**Органы управления.** Паттерн `<KIND>_<n>`. Все объекты с одним ключом — один орган.

| Вид | Класс | Что делает |
|---|---|---|
| `THROTTLE`, `TRAIN_BRAKE`, `IND(EPENDENT)_BRAKE`, `REVERSER` | рукоятки состава | перетаскивание со снапом к нотчу; реверсор 3 положения |
| `HANDBRAKE` / `HAND_BRAKE` | маховик ручника (RWAT) | клик затягивает или отпускает |
| `GAUGE_SPEED/THROTTLE/REVERSER/TRAIN_BRAKE/IND_BRAKE`, `BRAKE_PRESSURE` | прибор | показывает значение |
| `GAUGE_LIQUID/TEMPERATURE/BOILER_PRESSURE`, `COUPLED` | прибор | **всегда в покое** |
| `THROTTLE_BRAKE` | рычаг | **всегда 0.5** |
| `WIDGET`, `WINDOW`, `BELL/WHISTLE/HORN_CONTROL`, `ENGINE_START` | значение группы 0…1 | только свет, двери группы, `HIDE`-виджеты и другие органы той же группы. Тифон, свисток и звонок играют только с клавиш |

**Модификаторы органа:**
- `_CG_<группа>` — группа значения; без него группа = ключ;
- `_LABEL_<текст>` — подпись, `^` = пробел;
- `_OFFSET_<f>` — смещение значения;
- `_RANGE_<min>_<max>` — диапазон прибора;
- `TL_<f>_<ось>` — сдвиг;
- `<KEY>_ROT_<град>` — маркер шарнира: точка = центр, ось = длинная ось маркера;
- флаги `TOGGLE`, `PRESS`, `INVERT`, `HIDE` (прячет при значении 1, только `WIDGET`), `NOTOUCH`/`NOINTERACT`, `GLOBAL` (на весь состав).

**Свет**
- `_LCG_<группа>` — группа света, `LINVERT` — горит при выключенной группе.
- `FULLBRIGHT` — деталь светится при включённой группе; без `LCG` — всегда.
- Лампа салона — остров `FULLBRIGHT` с диагональю ≥ 0.3 в группе с `INTERIOR`-объектом. Цвета нет.
- `HEADLIGHT_<n>` — фара: ореол, луч 16 блоков, пятно на пути.
  - Направление ±Z — **по знаку положения**, не задаётся.
  - Цвет `_0X<RRGGBB>`.
  - Без `LCG` и при выключенном всём эффектов нет.
- Пределы: 64 группы на вагон, имя группы ≤ 32 символов, 16 групп света салона на странице «Состав».
- Нет: питания, мигания, фар по направлению хода.

## 6. Пульт и HUD машиниста

- HUD из модели **ничего не берёт**. Из типа он берёт `max_speed_kmh` (шкала) и `independent_kn > 0` (ряд вспомогательного тормоза).
- Модель нужна страницам пульта (список групп света) и подписи органа под прицелом.
- Имена групп света ищутся так:
  1. `light.<ns>.<type>.<группа>`;
  2. `light.railswheelsandtrains.<группа>` (в моде есть IL, FHL, RHL, FBL, RBL, BBL, FEL, REL, NL, BgL, BHL);
  3. `_LABEL_` органа;
  4. сам код группы.

## 7. Ходьба: пол, двери, кресла, корпус

**Пол** (`stock/FloorRegion.java`, `kinematics/RiderWalk.java`):
- пол = объединение **планов** зон, ужатое на полуширину игрока 0.3;
- касающиеся зоны сливаются; щель любой ширины — стена;
- высота под игроком — `min.y` **самой высокой** зоны над точкой;
- **предела высоты шага нет**: ступенька 0.2 и уступ 3 блока проходятся одинаково;
- пандусов нет, каждая зона плоская;
- вертикального движения нет: ни прыжка, ни падения, ни лестниц;
- потолок и рост не проверяются;
- зоны, перекрытые в плане на разных высотах, принимаются молча, но нижняя недоступна;
- **двухэтажный вагон не выразить.** 2D всё: `FloorRegion`, `clampFeet`, шаг, выход, переход, `FloorCheck`, `CabArea`, генератор. Высота двери не проверяется, а проём наружной двери не имеет нижней границы.

**Многоугольники пола и разметка в OBJ** (`FLOOR_n`, `SEAT_DRIVER`) **решены, но не сделаны.**

**Двери.** Ориентация выводится из коробки: тоньше по X — боковая, иначе торцевая. Наружу — по знаку центра.

| Вид | Поведение |
|---|---|
| наружная (без флагов) | закрыта — край пола; открыта — проём в корпусе (только для игроков), выход шагом |
| `connecting` | торцевая дверь на переход; шаг в открытую переносит к соседу (телепорт ~2 блока, гармошка не ходима); у соседа нужна открытая встречная дверь |
| `inner` | между зонами; закрытая — стена, только если между зонами щель; открытая — мостик ±0.6 |
| `fixed` | проём без створки, всегда открыт, не кликается: подножка, постоянный проход |
| `group` | двери группы открываются вместе; тумблер `CG` открывает двери с id или group = имени при значении ≥ 0.5 |

- Без наружных дверей вход и выход — по ПКМ.
- Длительность анимации одна на всех (40 тиков). Створки не имеют коллизии. Автозакрытия нет.

**Кресла:**
- только машиниста (`cab.seats`) и только при наличии `interior`;
- тип с `cab`, но без `interior` — одно ванильное место, паком не задаётся;
- **мест пассажиров нет**: ходячий пассажир всегда стоит, `SEAT_*` только рисуются.

**Корпус снаружи:**
- **одна коробка на вагон**: X ±1.7, Y 0.4…4.7, Z ±length/2 (`WagonType.java:583-601`);
- из пака влияет только `length`, ключа `hull` нет;
- у MVP кузова до ±1.87 в ширину и до 6.5 в высоту — выступают из корпуса;
- над открытой платформой стоит невидимая стена высотой 4.7;
- внутри вагона коллизии нет, есть только пол.

## 8. Звук и тряска

Ключ `sounds` декларации модели (`client/sound/SoundSet.java`).

| Ключ | Формат | Что делает |
|---|---|---|
| `idle` | петля | двигатель, высота и громкость по тяге |
| `wheels` | петля | ход, по скорости; без звука — вагонетка |
| `horn`, `bell` | петля | тифон и свисток по клавишам H и J; **`pitch`/`volume` игнорируются** |
| `clack` | ссылка | стык под каждой тележкой; шаг стыков 25 м зашит, формулы зашиты |
| `doors` | `{id двери: ссылка}` | один звук на открытие и закрытие |
| `controls` | `{КЛЮЧ: {move, engage}}` | **играют только** `THROTTLE_`, `TRAIN_BRAKE_`, `IND_BRAKE_`, `REVERSER_`; `WIDGET_*`, `ENGINE_START`, `COUPLER_ENGAGED_*` принимаются и молчат |

- **Петля** — строка или `{start?, main, stop?, pitch: [от, до], volume: [от, до]}`.
- **Ссылка** на `.ogg` — файл в паке; иначе это id звукового события. Ванильные звуки — с явным `minecraft:`.
- Ошибка в `sounds` выбрасывает **всю** декларацию модели.
- **Тряска:** `sway` 0…3 в модели; осцилляторы зашиты.

## 9. Стили рельсов — `assets/<ns>/rail_models/<id>.json`

**Два ключа:** `obj` (обязателен) и `tile_length` (> 0, по умолчанию 1). Встроенный — `railswheelsandtrains:standard`.

**Объекты тайла:**
- имя с `RAIL_`, без `BASE` — рельс;
- сторона рельса — по знаку z каждого квада; LEFT/RIGHT в имени не важны;
- всё остальное — основание: шпалы, балласт, мост;
- `HIDE` — не рисуется.

**Растяжение:** рельсы тянутся по X на `[-L/2, L/2]`, основание — нет.

**Полотно и коллизия:**
- сервер растрирует проекцию **всей** модели в столбцы блоков полотна на высоте подошвы рельса;
- высота модели на полотно не влияет;
- насыпь или настил моста своей коллизии не получают;
- 13 материалов полотна — enum в коде, паком не добавить.

**Стрелки** вырезаются из профиля рельсов сами. Остряки и крестовина появляются, только если головки рельсов накрывают |z| = 0.8125.

**Нет:** колеи (одна, ±0.8125), высоты головки (0.40625 зашита), своих моделей стрелок, перевода имени стиля на другие языки в конвертере.

После правки OBJ рельса нужны F3+T (картинка), `/reload` (полотно новых построек) и `/rwat rail rebed` (уже уложенное полотно).

## 10. Предметы, имена, загрузка

**Предметы:**
- один предмет «подвижной состав» на всё. Экран выбора — список типов сервера по id, без категорий, поиска и иконок; 3D-превью; ливреи — сырыми id;
- один предмет «рельсы»: стиль и материал полотна;
- вкладка творческого режима — 7 фиксированных предметов.

**Lang-ключи:**
- `wagon.<ns>.<id>`;
- `rail.<ns>.<id>`;
- `light.<ns>.<type>.<группа>`.

Ливреи, подписи `_LABEL_` и описания не локализуются; описаний нет вообще.

**Загрузка:**
- `<игра>/rwat_packs/` плюс `-Drwat.packDirs`;
- пак обязательный, всегда сверху, сам включается в мирах;
- при совпадении файла побеждает верхний пак целиком, слияния нет;
- общие текстуры между паками — только через явный `ns:` в путях, механизма зависимостей нет.

**Перезагрузка:** F3+T — модели, рельсы, звуки; `/reload` — типы и полотно.

**Ошибки** — только в логе.

**Раздачи пака сервером нет:** клиенту синкаются только типы.

## 11. Конвертер IR → RWAT (`tools/ir2rwat.py`)

**Рецепт `packs/<имя>.json`:**

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `namespace`, `sources[{zip, root, label}]`, `pack_dir` | обязательны | `out` обязателен без `--out` |
| `id_strip_prefix` | `""` | срезается с id |
| `exclude` | `[]` | пропустить типы |
| `overrides` | `{}` | оверрайды прямо в рецепте |
| `overrides_dir` | — | файл на тип, поверх `overrides` |
| `rail_exclude` | `[]` | пропустить треки |
| `rail_overrides` | `{}` | deep-merge в декларацию стиля |
| `sound_defaults` | `{}` | `{wheels: {категория: путь}, clack}` |
| `description`, `name`, `license` | — | в `pack.mcmeta` |
| `copy_root_files` | `[]` | из первого источника |

**Файл оверрайда типа `packs/<имя>/<id>.json`:**
- `name` и `lights` — в lang;
- `type` — deep-merge в тип. `type.doors` списком заменяет выведенные, объектом правит по id;
- `model` — deep-merge в модель;
- `floor` — опции генератора: `level`, `add`, `remove`, `ignore`, `clearance`, `slab`, `cell`, `step_down`; `false` выключает;
- `sway`;
- `null` удаляет поле.

**Будет ли работать на чужом IR-паке.** id MVP в коде не зашиты, но есть допущения:
1. ассеты строго под `assets/immersiverailroading/models/`;
2. пути только в нижнем регистре: одна заглавная буква — тип пропущен;
3. категория = папка;
4. тяга только у `locomotives` с `horsepower`;
5. диапазоны двигателя только для `era` `diesel`/`electric` (у всего MVP `diesel`);
6. калибровки `Y_LIFT` и `IR_FLOOR_OFFSET` замерены на MVP;
7. ручник ищется по подписи `hand^brake` — это соглашение MVP.

**Читается из IR:**
- `name`, `model`;
- `weight_kg`, `horsepower`, `tractive_effort_lbf`, `max_speed_kmh`;
- `trucks`, `couplers`, зона `passenger`;
- `tex_variants`, анимации дверей, `sounds`, `era`.

**Игнорируется:**
- `fuel_*`, `tiltMultiplier`, `passenger.slots`, `freight`, `tank`;
- `animations[].mode`/`frames_per_tick`;
- `materials` треков, индексы `stock.json`/`track.json`.

## 14. Найденные баги и расхождения с SPEC

**Баги** (проверены по коду, кроме помеченного):
1. **Битые `aliases` оставляют тип загруженным.** Тип кладётся в реестр до разбора алиасов, а в лог пишется «Skipping bad wagon type». Тип живёт без алиасов и без проверки `FloorCheck` (`data/WagonTypeReloadListener.java:61-63`). Если на один старый id претендуют два типа, побеждает первый по порядку `HashMap` — недетерминированно.
2. **`doors[].group: ""` у клиента становится `null`, у сервера — `""`.** Группировка дверей расходится (`network/WagonTypesPayload.java:108,114-116`).
3. **`brakes.dynamic_kn` и `dynamic_fade_kmh` парсятся и синкаются, но в физике не участвуют.**
4. **У `horn` и `bell` игнорируются `pitch`/`volume` из пака** (`client/sound/TrainSounds.java:382-387`).
5. **Звуки `controls` для `WIDGET_*`, `ENGINE_START`, `COUPLER_ENGAGED_*` принимаются и не играют.** Это 166 + 3 + 54 записи в MVP. При нескольких `THROTTLE_n` с разными звуками играет случайный.
6. **Несимметричные тележки** (`dr1a` 8.652 / −9.285): модель рисуется в середине тележек, а сцепки считаются от центра типа. Сдвиг около 0.3 блока — по коду, в игре не проверено.

**Расхождения SPEC с кодом:**
- §5.3 называет поля тормозов `force_kn`/`fade_kmh`, а парсер читает `train_kn`, `independent_kn`, `dynamic_kn`, `dynamic_fade_kmh`, `parking_kn`. Ключи из SPEC молча игнорируются.
- §5.2 говорит про N тележек — в коде две.
- §6.3: «всегда пропускаются `*HIDE*`» — в коде `WIDGET` и `COUPLED_*` исключения.
- §6.10 обещает место под колею в декларации стиля — такого ключа нет.
- §9.8 описывает многоугольники пола как принятые — в коде только коробки.
- v1.5: «Interior — один AABB» и NBT `Doors` — устарело (список зон, `OpenDoors` по id).
- README: «оверрайды в разделе `overrides` файла `mvp.json`» — на деле `overrides_dir`.
- Комментарий `WagonEntity.java:85-88` («дверь соседа открывается сама») — устарел.

## 15. Что это значит для редактора

**Редактор строится от схемы.** Описание полей (тип, единицы, умолчание, диапазон, подсказка) живёт в одной JSON Schema формата. Редактор рисует формы по ней, тогда новая возможность движка — это правка схемы, а не переписывание редактора. Пространственные вещи (пол, двери, кресла, фары, шарниры) требуют своих инструментов в 3D-виде.

**Что придётся повторить на JS** (и держать в синхроне общими тестовыми данными, которые гоняют и Java-, и JS-тесты):
- разбор имён `ObjectRole`;
- объединение и ужатие пола `FloorRegion`, проверки `FloorCheck`;
- ось шарнира `PivotAxis`;
- чтение `.anim`;
- вывод дверей и пола (сейчас в конвертере);
- пересчёт координат IR ↔ RWAT.

### План расширения движка (предложение, по приоритету)

**Ярус 0 — гигиена формата, до редактора (S):**
- версия формата в паке;
- предупреждения о незнакомых ключах, понятные ошибки вместо падения на `null`;
- ошибки паков в игре (`/rwat packs`);
- JSON Schema;
- починить баги §14;
- поправить SPEC.

**Ярус 1 — дёшево и сильно расширяет контент (S–M):**
- корпус из пака: `hull` с шириной и высотой, по умолчанию — bbox модели;
- отсечение и поиск коллизии от длины типа, а не константой;
- многоугольники пола (решено 2026-10-10);
- радиус колеса по мешу, вращение `FRAME_WHEEL_*`;
- длительность анимации двери в паке;
- полупрозрачность (стёкла) — отдельный проход рендера.

**Ярус 2 — средние (M):**
- **постоянная сцепка и наборы**: «единица» из N вагонов ставится одним предметом, монтировка её не расцепляет. Нужна ЭР2, ДР1, 2ТЭ116, паровозу с тендером;
- **анимации по группе управления и состоянию**, не только двери: токоприёмники, окна, дворники, по скорости или тяге;
- места пассажиров (`SEAT_*`);
- предел шага и пандусы;
- разметка в OBJ (`FLOOR_n`, `SEAT_DRIVER`), решена 2026-10-10;
- функции органов: тифон, свисток, звонок с рычагов в кабине;
- предметы с иконками и категориями.

**Ярус 3 — крупные (L):**
- **многоуровневый пол** (двухэтажные вагоны, лестницы);
- **N тележек и сочленение** (Якобс, трамваи);
- **паровоз**: ведущие колёса, дышла, кулиса, физика пара, топливо и вода, дым;
- **колея и высота рельса** в стиле и типе, совместимость;
- груз;
- раздача пака сервером клиентам.
