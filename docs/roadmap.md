# Дорожная карта RWAT (2026-11-02)

**Цель:** довести систему паков до ума. Конвертировать IR-пак и сделать свой пак с нуля должно быть удобно, в том числе в веб-редакторе. Движок при этом расширяется так, чтобы паки покрывали не только одноэтажные вагоны.

**Это главный план работ.** Подробности по пунктам живут в документах-основаниях, которые остаются справочниками:
- `docs/reviews/2026-10-15-code-audit.md` — аудит кода, находки H/M/T;
- `docs/reviews/2026-10-15-pack-authoring.md` — ревью удобства паков;
- `docs/reviews/2026-10-21-fix-list.md` — партии A–F, решения D1–D5 (партии B, C, E берутся оттуда без изменений);
- `docs/reviews/2026-10-21-batch-a.md` — отчёт партии A;
- `docs/proposals/pack-capabilities.md` — что пак может задать и где кончается движок.

### Фаза 1 — формат v1

Партия D, ярус 0 и F3–F5. Одна партия = один пулл-реквест.

1. **`CLAUDE.md`** — правила для агентов (R16).
2. **Схема `schema/`:**
   - тип вагона, модель вместе со звуками, стиль рельсов;
   - блок `rwat` в `pack.mcmeta`: версия формата, имя, авторы, лицензия;
   - рецепт и файл оверрайда конвертера;
   - тест «схема = ключи парсеров».
3. **Строгая загрузка:**
   - незнакомый ключ — предупреждение с подсказкой ближайшего известного;
   - `null` — понятная ошибка вместо падения;
   - проверка геометрии (D3): `length > 0`, порядок тележек, границы сцепок;
   - `group: ""` = нет группы; группы дверей везде без учёта регистра;
   - модель без типа — предупреждение (D4).
4. **Ломающие изменения v1 — одним разом:**
   - координаты разметки в кадре OBJ (R6) с переводом оверрайдов MVP, `floorgen`, `objinfo` и тестов;
   - номер формата `rwat.format: 1`.
5. **Ошибки паков в игре:**
   - `/rwat packs` — паки, типы, ошибки и предупреждения;
   - сообщение операторам при входе, если есть ошибки;
   - `/rwat packs validate` — загрузить все OBJ сразу (офлайн-валидатор из ревью паков).
6. **Жизненный цикл:**
   - `/reload` пересобирает составы на сервере (D1);
   - алиасы в одиночной игре (D2);
   - битые `aliases` больше не оставляют тип загруженным, коллизия алиасов детерминирована;
   - общий разбор стиля рельсов с нижней границей `tile_length` (D5);
   - устойчивая загрузка (D7).
7. **Звук:** тифон и свисток берут `pitch`/`volume` из пака; `trainVolume > 1` (остаток D8).
8. **Конвертер и инструменты (D9) плюс работа на чужих IR-паках:**
   - нет жёсткого пути `assets/immersiverailroading/`;
   - пути в любом регистре;
   - понятные ошибки вместо трассировок.
9. **Сверка паков клиента и сервера по хешам** (R15).
10. **Документы и пример:**
    - справочник автора `docs/pack-format.md` генерируется из схемы;
    - README;
    - SPEC §5.3: имена полей тормозов;
    - пак-пример `run/rwat_packs/RwatExamplePack` (R11).

**Готово, когда:**
- пак-пример грузится без единого предупреждения;
- тест схемы зелёный;
- MVP перегенерирован и отличается от прежнего только переведёнными координатами.

## Как работаем

Правила из списка исправлений остаются:
- партия = пулл-реквест;
- агенты работают параллельно на непересекающихся файлах;
- я проверяю каждый дифф, гоняю тесты и автосцены и только потом сливаю;
- ворота: сборка и тесты зелёные; для чистого кода — тест, который падал до исправления; для игрового — автосцена или снимок; комментарии и SPEC правятся в том же коммите.

Добавляется:
- **работу выполняют агенты** (решение пользователя 2026-11-02). Основная сессия — дирижёр: ставит задачи, разводит агентов по непересекающимся файлам (каждый в своей копии репозитория), проверяет диффы, сливает, гоняет тесты;
- **формат меняется только вместе со схемой**, расхождение ловит тест;
- **логика, у которой есть порт** (Java, TypeScript, Python), меняется во всех портах сразу, эталонные данные общие.

## Не делаем

- Нативную поддержку RTM или IR в моде: чужие форматы — только через конвертер.
- Правку сгенерированного пака MVP руками или в редакторе: правится рецепт.
- Свободную физику твёрдых тел и хождение по вагону в мировых координатах (анти-скоуп SPEC).
