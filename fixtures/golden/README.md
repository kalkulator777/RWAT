# Эталонные данные (golden)

Общий вход для тестов логики, у которой есть порты (решение R9 в `docs/roadmap.md`, требования — `docs/proposals/editor.md`, 4.4–4.5):
- эталон — Java (источник правды) или, для `json_dump` и `validate`, Python;
- порты — Python-инструменты в `tools/` (только портированное) и TypeScript веб-редактора (`editor/src/ports/`).

Расхождение порта с эталоном ловит тест того порта, который разошёлся.

## Раскладка

```
fixtures/golden/
  schema.json            схема формата: файл случаев, ports.json ($defs/ports), находка ($defs/finding)
  README.md
  <папка>/               одна логика, имена — из таблицы editor.md 4.1
    ports.json           {"reference": "java" | "python", "ports": ["ts", "python", …]}
    <файл>.json          случаи; файлов сколько угодно, тесты читают все *.json папки
```

- **Одна папка — одна логика.** Ни один тест не перечисляет файлы руками: раннер папки читает все её `*.json`, кроме `ports.json`. Новый файл в папке не требует правки раннеров.
- **`ports.json` — кто читает папку.** Эталон пишет ожидаемое, порты сверяются с ним. Мета-тест каждого набора проверяет, что каждую папку, где назван его язык, читает раннер: `GoldenFoldersTest` (Java), `test_golden_folders.py` (Python), в редакторе — свой.
- **Раннер — файл на логику:** `src/test/java/…/golden/<Logic>Golden.java` (папка `floor_check` → `FloorCheckGolden`, константа `FOLDER`), `tools/tests/test_golden_<папка>.py`, `editor/src/ports/<logic>.test.ts`. Общая часть: `Golden.java`, `tools/tests/golden.py`.

## Формат файла

```json
{
  "description": "какая логика (класс и метод эталона), что во входе и в ожидаемом",
  "frame": "obj",
  "tolerance": 1e-9,
  "cases": [
    {"id": "a-blank-inside", "note": "зачем случай", "input": {…}, "expected": …}
  ]
}
```

- **`id`** — стабильный, `^[a-z0-9]+(-[a-z0-9]+)*$`, уникален в папке: по нему находят упавший случай в отчётах всех портов (в Java — имя динамического теста, в Python — `subTest`).
- **`note`** — зачем случай. Тексты файлов — по-английски, как код.
- **`input`** — вход в том виде, в каком его читает движок: текст OBJ, MTL и `.anim` строкой, имена объектов строками, тип — JSON формата пака в кадре OBJ, как в файле.
- **`input_file`** — вход из файлов пака-примера `run/rwat_packs/RwatExamplePack/…` (CC0), путь от корня репозитория. Строка — весь вход это файл; объект — файлы кладутся во `input` под своими ключами. Файл `.json` читается как JSON, прочие — как текст UTF-8. Других файлов нет: ни MVP, ни чужих ассетов (R12). Порт, которому важны числа как записаны (`json_dump`), читает такой файл сам.
- **`expected`** пишет эталон, руками его не правят. Новый случай пишется с `"expected": null` и заполняется флагом обновления.
- **`frame`** — кадр мест в ожидаемом: `obj` (кадр пака, как в Blender), `model` (кадр движка, `stock.ObjFrame`) или `none` (мест нет). Разметка во входе — всегда в кадре OBJ. Вопрос к результату (точка для `fits`, `doorHolding`…) задаётся в кадре ожидаемого.
- **`tolerance`** — абсолютный допуск порта для чисел: `1e-9` для логики в `double`, `1e-6` для `float`, `0` для текста и правил чисел Java. Эталон сверяет точно.
- **Числа.** `NaN` и бесконечности записываются строками `"NaN"`, `"Infinity"`, `"-Infinity"` (во входе и в ожидаемом). Значения `float` — кратчайшей записью `float` (`0.6`, а не `0.6000000238418579`): `Math.fround` от неё даёт то же `float`. Исключение — `java_numbers/parse_float.json`: там точное значение `float` в `double`, допуск 0.
- **Находка** (`$defs/finding`) — то, что движок пишет автору пака: `{code, subject, index, params, text}`. Пока движок отдаёт только текст (сообщения разбора типа в `wagon_type`), `code`, `subject`, `index` — `null`, `params` — `{}`.

## Как сверять

- **Эталон** сверяет `expected` с результатом как JSON, точно: значения посчитал он сам.
- **Порты** (`tools/tests/golden.py`, `close`):
  - числа — с допуском файла: порядок операций с плавающей точкой может отличаться;
  - `"NaN"`, `"Infinity"`, `"-Infinity"` совпадают с этими значениями (и с такой же строкой);
  - строки, логические значения и `null` — точно; `null` не совпадает с NaN;
  - объекты — те же ключи в том же порядке, массивы — поэлементно.
- Порт сверяет то, что портировал: Python, например, в `obj` — только имена объектов, в `floor_check` — только выходы (`exits_of`). Что именно — в docstring раннера.

## Как обновить

Логика поменялась намеренно или добавлен случай:

```sh
./gradlew test --tests 'com.muzhik17.trainsmod.golden.*' -Pgolden.update   # папки, где эталон — Java
python -I tools/tests/test_golden_json_dump.py --update                     # папки, где эталон — Python
python -I tools/tests/test_golden_validate.py --update
git diff fixtures/golden      # каждое изменённое ожидание должно быть объяснимо
./gradlew test                # без флага всё зелёное
python -I -m unittest discover tools/tests
```

- С флагом раннер эталона переписывает `expected` каждого случая из кода и раскладывает файл заново (два пробела, массив или объект в строку, пока влезает в 110 знаков; файл, его `cases` и каждый случай — по ключу в строке). `build.gradle` передаёт `-Pgolden.update` в JVM тестов свойством `golden.update`; другого способа нет.
- Без флага тест только сверяет и при расхождении называет папку, файл и `id`.
- Изменённые эталоны коммитятся вместе с правкой кода и правкой портов (editor.md 4.4).
- Порт, который разошёлся с эталоном, правится сам, а не через эталон. TypeScript ожидаемое не пишет никогда.

## Пределы

Файл — не больше 200 КБ, папка `fixtures/golden/` целиком — не больше 3 МБ, в папке логики — не меньше 10 случаев (проверяют раннеры и `test_golden_folders.py`). Это тест, а не склад моделей.

## Что знать порту

- **Числа Java (`java_numbers`).**
  - `Float.parseFloat` отказывает целой строке, а не читает префикс (`"1.5abc"` — отказ, JS `parseFloat` даёт 1.5); принимает суффиксы `f`/`d`, шестнадцатеричное `0x1p3`, `NaN`, `Infinity`, пробелы до U+0020 по краям; не принимает `nan`, `inf`, неразрывный пробел, `0x10` без двоичного порядка.
  - Чтение сразу во `float`, а не через `double`: `fround(parseFloat("1.0000000596046447753906250001"))` округляет дважды и даёт 1, Java — `1.0000001192092896`.
  - `%.Nf` округляет **половину вверх от кратчайшей десятичной записи** `double`: `1.005` → `1.01`, `2.675` → `2.68`, `0.35` → `0.4` (JS `toFixed` даёт `1.00`, `2.67`, `0.3`); `2.5` при `%.0f` → `3`. Минус ноль печатается со знаком: `-0.0` и `-0.001` → `-0.00`. Большие числа — целиком, без экспоненты (`1e21` → `1000000000000000000000.0`). `NaN` и бесконечности печатаются как `NaN`, `Infinity`, `-Infinity`.
- **Тексты `FloorCheck`** (дословно, вместе с числами):
  - `%.2f` и `%.1f` — правило выше; бесконечное расстояние и NaN высоты (на полу некуда встать) печатаются `Infinity` и `NaN`;
  - запас у двери (`slack`) — как `Double.toString`: `0.4`, целое — `1.0`;
  - список зон — `[1, 2]` (`List.toString`);
  - место кресла — в кадре OBJ, `x = -z` модели: кресло на `x = -0.0` печатается `-0.00`.
- **Сообщения разбора типа (`wagon_type`).** Число из файла в ошибке «не того типа» — как записано в файле (`the number 1`); число в ошибке геометрии — целое без `.0`, иначе как `Double.toString` (`1.0E-5`). Подсказка к незнакомому ключу — `PackJson.nearest` движка, не `suggestion` из `validate_pack` (та — в `validate`).
- **Шарнир (`pivot_axis`).**
  - Углы — `float32`, как их читает загрузчик OBJ: в TypeScript `Math.fround` каждой координаты до расчёта. Сам расчёт идёт в `double`.
  - Порядок углов важен. Ничьи: конец A и конец B — первая по порядку из равноудалённых точек; точка на равном расстоянии от ближнего и дальнего концов не входит ни в одну половину. У симметричного маркера (коробки) знак оси решает первая вершина файла, как в IR.
  - Точки — каждая позиция один раз, первое появление; `-0` и `0` — одна позиция.
  - Из текста OBJ углы — все углы всех граней всех частей объекта по порядку, как их хранит загрузчик: четыре у квада, у треугольника последний дважды, многоугольник веером от первого угла.
- **OBJ (`obj`).** `v` у вершины — `1 − v` файла (Minecraft берёт V сверху); без `vt` — `u = 0`, `v = 0`; без `vn` — нормаль `0 1 0`. Отрицательный индекс, вершина «из будущего», мусорное число — отказ всего файла (`{error: true}`). Координаты — `Float.parseFloat` (см. выше).
- **`.anim`.** Кадры — `float32`, по строкам, как в файле.
- **Пол (`floor_region`).**
  - Тип — в кадре OBJ, ответы и вопросы — в кадре модели: так тип хранит движок, редактор переводит разметку через `obj_frame`.
  - `margin` по умолчанию — 0.3, полуширина игрока; 0 движок не принимает.
  - Дверь режет пол, только если она `inner`, не `fixed` и закрыта (бит `open`, только первые 32 двери).
- **Створки (`door_leaves`).**
  - Тип для поиска двери — обёртка `{"length": 30, "bogies": [8, -8], "mass_t": 40, "doors": …}`: на ответ влияют только двери.
  - Коробка створки — объединение коробок объектов с текстурой. Её центр переводится в кадр модели и ищется в коробках дверей с запасом 0.1.
- **Пробелы.**
  - Имена объектов: пробелом считаются символы до U+0020 (как `String.trim`). Неразрывный пробел — часть имени.
  - Имена материалов: случаи только с ASCII-пробелами. На прочих пробелах Unicode Java и Python расходятся: `Character.isWhitespace` против `str.split`.
- **`json_dump`.** Числа — как их пишет Python: `100.0` остаётся `100.0`, `1e2` — `100.0`, `-0` — `0`, `1e16` — `1e+16`, `1e-5` — `1e-05` (JS пишет `10000000000000000` и `0.00001`); целые за 2^53 — точно. Порту нужно читать JSON без потерь: `JSON.parse` склеивает `100.0` и `100`.
- **`validate`.** Указатель — RFC 6901, `""` — весь документ. Ajv формулирует находки иначе: порт сверяет места и важность, текст — справочно; подсказку к незнакомому ключу — по `suggestion`.

## Чего нет и почему

- **Выбор кадра `.anim` и интерполяция** (`frameAt`: кадр = прогресс × (N − 1), поэлементно) живут в `client/render/WagonRenderer` с Minecraft: эталону нечего вызвать. Нужна чистая точка входа (например, `IrAnim.frameAt(frames, progress)`).
- **`StockModel.Control.transform`** — в классе с `ResourceLocation`, которого нет в тестовом classpath: `ControlPoseGolden` строит орган и зовёт его метод отражением, код движка тот же. Чистый дом для преобразования убрал бы отражение.
- **Выходы `floor_check`** берутся из `FloorCheck.walkablePieces` (пакетный доступ) отражением.
